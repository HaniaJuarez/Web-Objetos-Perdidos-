# Objetos Perdidos - Facultad

Sistema web para la gestión de objetos perdidos y encontrados de la facultad.
Desarrollar un sistema web que permita el registro, consulta, localizacion 
y seguimiento a objetos perdidos y encontrados dentro de la facultad
## 1. Descripción del sistema

*Objeto Perdidos* es un sistema web diseñado para facilitar la gestión de objetos perdidos y encontrados dentro de un entorno universitario. Su propósito es centralizar la información relacionada con los objetos extraviados, proporcionando un espacio digital que facilite la comunicación entre los integrantes de la comunidad universitaria y contribuya a la recuperación de sus pertenencias.

El sistema busca reducir la dependencia de medios informales para compartir información sobre objetos extraviados, ofreciendo una plataforma accesible, organizada y con una interfaz intuitiva.

El proyecto se desarrolla como parte de un proyecto académico de la carrera de Ingeniería en Tecnologías Computacionales de la Universidad Veracruzana.
## 3. Características del sistema

* Interfaz web para la interacción con los usuarios.
* Organización de la información relacionada con objetos perdidos y encontrados.
* Gestión de información mediante una base de datos.
* Acceso a las funcionalidades del sistema de acuerdo con las características implementadas.
* Diseño de una interfaz intuitiva y adaptable a las necesidades de los usuarios.
* Integración de tecnologías para el desarrollo del frontend, backend y almacenamiento de información.

## 5. Requerimientos del sistema

### 5.1. Requerimientos de hardware

* Computadora de escritorio o portátil.
* Procesador compatible con un navegador web moderno.
* Memoria RAM suficiente para ejecutar el sistema y las herramientas de desarrollo.
* Conexión a Internet para acceder a los servicios remotos utilizados por la aplicación.

### 5.2. Requerimientos de software

* Sistema operativo Windows, Linux o macOS.
* Navegador web actualizado, como Google Chrome, Mozilla Firefox o Microsoft Edge.
* Servidor web compatible con PHP para ejecutar la aplicación localmente.
* PHP con una versión compatible con el proyecto.
* Cuenta y proyecto configurados en Supabase, si se utilizan sus servicios remotos.
* Git, opcional para clonar el repositorio y administrar las versiones del proyecto.

### 5.3. Requerimientos funcionales

* Presentar una interfaz para acceder a las funcionalidades del sistema.
* Organizar la información de objetos perdidos y encontrados.
* Permitir la interacción con la información almacenada según las funciones implementadas.
* Gestionar el acceso de los usuarios, si se encuentra habilitado el módulo de autenticación.
* Mantener la comunicación entre la aplicación y la base de datos.

### 5.4. Requerimientos no funcionales

* *Usabilidad:* ofrecer una interfaz clara y fácil de utilizar.
* *Seguridad:* proteger la información y restringir el acceso a las operaciones autorizadas.
* *Disponibilidad:* permitir el acceso al sistema cuando el servidor y los servicios asociados estén operativos.
* *Mantenibilidad:* organizar el código para facilitar futuras modificaciones.
* *Compatibilidad:* permitir el uso desde navegadores web modernos.

La organización general del repositorio contempla los siguientes componentes:

La estructura exacta puede variar según los módulos incorporados durante el desarrollo.

## 7. Instalación y ejecución

Para ejecutar el sistema en un entorno local:

1. Instalar un entorno de servidor web compatible con PHP, como XAMPP.
2. Clonar el repositorio de GitHub o descargar sus archivos.
3. Colocar el proyecto dentro del directorio correspondiente del servidor web.
4. Configurar las credenciales y los parámetros de conexión con Supabase en los archivos de configuración correspondientes.
5. Verificar que las tablas, políticas de seguridad y servicios necesarios estén configurados.
6. Iniciar Apache desde el panel de control de XAMPP.
7. Abrir el navegador y acceder a la ruta local correspondiente al proyecto.

*Importante:* la ruta exacta de acceso y la configuración de la base de datos dependen de la estructura actual del repositorio.
